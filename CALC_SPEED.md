# Расчёт скорости по speed.md

`src/calc_speed.py` по умолчанию использует `--mode physics`:
на каждом участке свободного полёта — заданном вручную через `--segment`
или найденном автоматически, если `--segment` не указан, — подбираются
`X0, Y0, Z0, Vx, Vy, Vz`. Центры сравниваются с обратной проекцией
параболы на видео. Диаметр `min(w_px, h_px)` даёт дополнительное ограничение
с меньшим весом. Используются `scipy.optimize.least_squares`, Soft-L1,
отдельный медианный фильтр размера и повторный fit после исключения
явных выбросов центра. Центры перед fitting не сглаживаются.

Пример запуска (4:18 — пример интервала для проверки, а не подтверждённая разметка касаний):

```bash
.venv/bin/python src/calc_speed.py \
  --court /mnt/data-ml/datashared/volleyball-demo/pro-bl-tula/json/pro-bl-tula-demo_001_court.json \
  --ball-boxes /mnt/data-ml/datashared/volleyball-demo/pro-bl-tula/json/pro-bl-tula-demo_001.json \
  --video /mnt/data-ml/datashared/volleyball-demo/pro-bl-tula/video/pro-bl-tula-demo_001.mp4 \
  --segment 4:18
```

Без `--segment` та же команда сама найдёт параболы:

```bash
.venv/bin/python src/calc_speed.py \
  --court .../pro-bl-tula-demo_001_court.json \
  --ball-boxes .../pro-bl-tula-demo_001.json \
  --video .../pro-bl-tula-demo_001.mp4
```

Для нескольких полётов повторите `--segment START:END`. Границы включительные,
в нумерации кадров видео с нуля; интервалы не пересекаются. `--frame-base`
относится только к входной разметке. Внутри интервала требуется минимум
6 центров, 3 пригодных размера и 0,1 с наблюдений. Пропуски кадров допустимы:
внутри fitted сегмента показывается предсказание, в CSV это отмечено статусом.
Вне заданных интервалов физическая скорость не вычисляется.

Чтобы посмотреть кадры вручную, запустите `--mode radius`. Клавиши A/D: −1/+1 кадр, W/S: +15/−15 кадров, пробел:
воспроизведение/пауза, Q/Esc: выход. Перемотка ставит видео на паузу.
Предварительный расчёт не зависит от порядка просмотра кадров.

Скорость в physics — мгновенная аналитическая производная fitted параболы,
а не смещение за окно. `--window 0.5` относится к прежним режимам
`--mode radius` и `--mode floor`. Физическая модель не должна проходить через
касание, отскок или блок. Сами события не классифицируются, но интервалы,
укладывающиеся в одну параболу, определяются автоматически (см. ниже).

## Автоматическое определение парабол

Если `--segment` не задан, интервалы свободного полёта ищутся автоматически:

1. разрыв в детекциях длиннее `--segment-max-gap` (0,25 с) всегда завершает
   полёт: за пропуском может скрываться касание;
2. резкий поворот или скачок видимой скорости мяча в кадре предлагает касание.
   Это только кандидаты: у высокой подкидки направление в кадре разворачивается
   и без касания;
3. решение принимает сам ballistic fit. Не подошедший интервал делится ещё раз
   по кадру с худшей ошибкой обратной проекции, а соседние интервалы
   объединяются обратно, если вместе они по-прежнему укладываются в одну
   параболу, — так вершина траектории не принимается за касание;
4. интервалы, которые так и не уложились в `--segment-max-rmse` (3 px)
   или оказались невалидными, отбрасываются.

Выводится строка `Automatic segmentation: N free-flight parabolas (...)`.
Кадр предполагаемого касания в интервал не входит, но момент и тип касания
не определяются: возвращаются только параболы. Ручной `--segment` полностью
отключает автоматику. `--net-crossing` вне найденных интервалов игнорируется
с предупреждением.

Требования к интервалу те же, что при ручной разметке: минимум 6 центров,
3 пригодных размера и 0,1 с наблюдений. Слабое касание без заметного излома
в кадре может остаться внутри интервала: тогда fit даёт большой RMSE, и такой
интервал отбрасывается, а не выдаётся как парабола. Результат нужно проверять
по `--plots`, `--report` и наложенной траектории.

## Геометрия и время

По умолчанию сохраняются размеры данного зального видео: площадка 9×18 м,
мяч 0,22 м, сетка 2,43 м. Для примера пляжной площадки из speed.md:
`--court-width 8 --court-length 16 --ball-diameter 0.21`.
Оси: X слева направо, Y от ближней линии к дальней, Z вверх.
Точки 6/7 должны быть концами сетки непосредственно над точками 4/5.
`--net-height` должен соответствовать именно размеченной высоте.

Неизвестная камера: оцениваются f, R, t при fx=fy, центре изображения
как principal point и нулевой дисторсии. Для отдельной калибровки используйте
`--intrinsics camera.json` с полями `K` (3×3, в пикселях видео) и `dist`
(коэффициенты OpenCV): положение камеры определяется через solvePnP.
Для размера мяча остаётся приближение маленькой сферы; сильная дисторсия
и bbox произвольной формы снижают точность этого ограничения.

Время берётся из PTS кадров через ffprobe. Если PTS недоступны, выводится
предупреждение и используется frame/FPS. Видео с переменным FPS рассчитывается
по PTS; сохранённый MP4 имеет постоянный FPS, а CSV и графики сохраняют исходные
временные метки.

Ограничения: X в [-2, width+2], Y в [-3, length+3], Z в [D/2, 15].
Проверяется весь интервал, включая вершину параболы. Нарушающий ограничения fit
помечается невалидным, и его скорость не выдаётся. При известном времени
пересечения плоскости сетки можно добавить `--net-crossing FRAME`:
оно ограничивает Y длиной/2. Пересечение картинки сетки автоматически
не используется как 3D-событие — из одного такого совпадения глубина не следует.

## Результаты и проверка

Опции (пути должны быть новыми):

- `--output result.mp4`: видео с наблюдаемым боксом/размером (голубой/жёлтый),
  fitted центром, размером и траекторией (розовый), видом сверху и видом сбоку.
- `--output-csv speed.csv`: покадровые координаты, Vx/Vy/Vz, модуль скорости,
  confidence, сегмент, ошибка проекции и предсказанный диаметр.
- `--report fit.json`: K/R/t/dist, положение камеры, временные метки,
  параметры сегментов, начальная/конечная/максимальная/средняя скорости,
  ошибки и маска выбросов. Скорости в отчёте — м/с.
- `--plots diagnostics.png`: X(t), Y(t), Z(t), скорость, наблюдаемый и
  предсказанный диаметры, ошибка обратной проекции.
- `--no-show`: обработка без окна. При экспорте с GUI сначала сохраняется
  полный результат, затем открывается просмотр, чтобы перемотка не портила файл.

Confidence — эвристическая метка, не вероятность и не гарантия точности.
Она учитывает число наблюдений, длительность, выбросы, ошибки центра/размера
и калибровки. Проверка на синтетических траекториях не заменяет проверку
реальной скорости радаром. Ошибка 5–10 км/ч пока не подтверждена.

